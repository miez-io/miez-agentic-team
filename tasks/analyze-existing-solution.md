description: Analyze an existing solution and document its requirements.
---

## What is the goal

Your goal is to understand the solution well enough to take ownership of it and guide its future roadmap.

## What to do

- Approach this as an architect joining a new project and taking over responsibility for it.
- Analyse an existing repository or, potentially, a workspace containing multiple repositories.
- Understand the complete solution from the code and documentation you find.
- Use your skillset to write and document the appropriate documents, if they do not already exist.
- In addition to the architecture documents, you may write personal notes or open questions for the user to answer.
- If the workspace contains multiple repositories, focus only on the applications the user mentions. If that is unclear, ask the user.

## What not to do

- Do not write decision records; this task documents the existing state only.
