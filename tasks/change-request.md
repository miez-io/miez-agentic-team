## What is the goal

The user requests one or more changes to an existing or planned solution.

Drive and determine the right approach for a change request, based on your persona, assigned skills, and the evidence in the repository.

## What to do

First, assess the request against the existing requirements, architecture
documentation, and implementation. Identify the requested outcome, affected areas, and any conflicts or missing information.

If the request is a compatible addition or a small correction:

- make the smallest appropriate change;
- update the affected architecture documentation and requirements; and
- verify that the change remains consistent with the existing implementation.

If the request changes existing requirements, responsibilities, boundaries, or
architecture:

- do not implement it blindly;
- explain the impact, alternatives, trade-offs, and open questions;
- create the necessary architectural plan and documentation; and
- ask the user for critical decisions or missing requirements before proceeding
	when they cannot be resolved from the available context.

Challenge assumptions when needed. The user's proposed solution may not be the
right direction; break the problem down and consider the whole system before
committing to an approach.
